# Tank Arena: ваш бот на Java 21

Версия SDK 3.5.1, протокол 2.13. Нужен сервер той же версии с профилем `combat.properties`.

Сервер принимает только протокол 2.13 с явным заголовком версии. Его отправляет SDK 3.5.1; прежний SDK 3.5.0 нужно обновить. После обновления репозитория выполните Reload Maven Project в IDE и заново запустите `Main`.

Если преподаватель обнулил участников, сохранённый токен больше не действует. На вопрос «Начать новую регистрацию?» ответьте `да`, затем укажите имя и общий пароль. Очки начнутся с нуля; потребуется новый допуск преподавателя.

## Запуск из IDE

1. Откройте корневой `pom.xml` как Maven-проект. Выберите JDK 21 для проекта и Maven.
2. Запустите `src/main/java/student/Main.java` кнопкой Run.
3. В консоли укажите адрес сервера, имя танка и общий пароль преподавателя. Дождитесь допуска.
4. Откройте напечатанный адрес `/combat.html`. Для личного обзора выберите файл токена, путь к которому показывает программа.

SDK и его исходники входят в `.mvn/repository`. Для первой загрузки Maven-плагинов и JUnit нужен интернет. Если сервер ещё использует старый протокол, сначала обновляется сервер: новый клиент не совместим с прежним режимом доставки.

Стартовый `MyBot` только появляется и возвращает бездействие. Движение, выбор действий, наведение, огонь, щит и вся архитектура управления остаются вашей работой.

```java
@Override
public Control decide(CombatObservation view) {
    return Control.idle(view.me().position());
}
```

`Control(throttle, turn, aim, fire, shield)` — низкоуровневое управление. [Поля и единицы](docs/student-api.md). Стратегия получает собственный снимок через `CombatObservation`, а не полный мир. В IDE доступны исходники SDK и Javadoc.

После смерти сервер сам возрождает танк, а SDK создаёт новый экземпляр бота. `Main` перезапускать не требуется. Живой танк при добровольном выходе или потере связи на 15 с теряет 100 очков и возвращается с базовым оснащением. Это закрывает бесплатное восстановление перезапуском. При подготовке и отладке ориентируйтесь на задачу и договорённости с преподавателем, а не только на текущий игровой счёт.

## Исходники сервера

В GitHub каталог `engine/` содержит полный производственный код ядра, протокола, SDK, HTTP-сервера и интерфейса. Это отдельный Maven-проект: откройте `engine/pom.xml`, выполните Maven `package` с параметром `-Dmaven.test.skip=true` либо запускайте `edu.arena.server.bootstrap.ServerMain` из IDE с рабочим каталогом `engine`.

Сервер читает `engine/config/combat.properties`. По умолчанию он слушает localhost:8080, допускает один активный танк и имеет 16 мест. Для аудитории преподаватель меняет адрес привязки и разрешает доступ к порту. Общий пароль задаётся в панели преподавателя; административный ключ создаётся только локально в серверном каталоге данных.

Не добавляйте в Git личные токены, ключ преподавателя или каталог данных сервера. Один адрес сервера сохраняет один аккаунт SDK; смена процесса сама по себе не обнуляет результат.

Автоматические тесты, игровой и нагрузочный прогоны не запускались. При публикации 3.5.1 проверены отказ старому протоколу, вход преподавателя и пустой список участников после сброса. Это не проверка игрового баланса. Коммит помечен `[skip ci]`.
