# Ваш танк на Java 21

Скачайте проект через **Code → Download ZIP** и распакуйте его либо клонируйте репозиторий средствами IDE.

Откройте `pom.xml` в IntelliJ IDEA или другой Java IDE как Maven-проект. Выберите **JDK 21** и дождитесь загрузки зависимостей. SDK арены включён в проект; для первого импорта Maven и JUnit нужен интернет.

Откройте `src/main/java/student/Main.java` и нажмите **Run** рядом с методом `main`. Скрипты и параметры запуска не нужны.

## Первый запуск

В консоли IDE последовательно введите:

1. Адрес сервера, который сообщил преподаватель.
2. Имя своего танка.
3. Пароль сервера, который сообщил преподаватель. Он общий для группы.

Клиент дождётся допуска преподавателя и подключит танк. Откройте напечатанный адрес в браузере, чтобы наблюдать бой. Ключ из `admin-key.txt` предназначен для входа преподавателя в админку; в студенческий клиент его вводить не нужно.

Исходный бот стоит на месте: не движется, не целится, не стреляет и не включает щит. Защиту при появлении и возвращение после смерти обеспечивает сервер.

Если преподаватель дал HTTP-адрес в сети аудитории, клиент попросит явно разрешить незашифрованное подключение. Для внешнего сервера нужен HTTPS.

При повторном запуске укажите тот же адрес. Пароль больше не понадобится: клиент сохраняет ваш личный ключ. Нажмите Enter в поле имени, чтобы сохранить прежнее, или введите новое. Очки принадлежат аккаунту. Ключ подключения хранится вне проекта: в домашней папке пользователя, `.tank-arena/players`. Не передавайте эти файлы другим. Смена общего пароля не затрагивает ваш аккаунт.

## Где писать код

В проекте два исходных файла:

| Файл | Назначение |
|---|---|
| `Main.java` | Запуск приложения и создание нового бота для каждой жизни |
| `MyBot.java` | Ваши решения на каждом шаге арены |

Единственный игровой контракт — `Bot.decide(Observation) → Control`. Вы получаете снимок арены и возвращаете одну команду. Какие методы, классы и состояния вам понадобятся, решаете самостоятельно.

| Данные снимка | Что находится внутри |
|---|---|
| `view.me()` | Ваш танк: положение, скорость, здоровье, направление, перезарядка и щит |
| `view.opponents()` | Живые противники |
| `view.state()` | Текущий шаг, танки, снаряды и события |
| `view.map()` | Размер поля и препятствия |
| `view.rules()` | Скорости, ограничения и длительности игровых механик |

В IDE можно перейти к определениям `Bot`, `Observation`, `Control` и других типов через **Go to Declaration**. Исходники SDK включены в комплект; описание каждого аргумента `Control` доступно прямо в IDE.

## Пять полей Control

```java
new Control(throttle, turn, aim, fire, shield)
```

Координаты отсчитываются от левого верхнего угла: X растёт вправо, Y — вниз. Расстояния измеряются в единицах игрового мира, а не в пикселях браузера. Направления танка и башни выражены в радианах: 0 — вправо, π/2 — вниз. Один игровой шаг длится `1.0 / view.rules().tickRate()` игровых секунд.

### `throttle` — движение вдоль корпуса

Число от **−1 до 1**: `1` — вперёд, `−1` — назад, `0.5` — вперёд с половинной скоростью, `0` — остановка. Максимальная скорость равна `view.rules().moveSpeed()` единиц мира за игровую секунду. Значение задаёт скорость, не ускорение: инерции нет. Задний ход не разворачивает танк.

Двигаться и поворачивать можно одновременно. Движок сначала поворачивает корпус, затем перемещает его вдоль нового направления. Стены и другие танки ограничивают движение.

### `turn` — скорость поворота корпуса

Число от **−1 до 1**: положительное — по часовой стрелке, отрицательное — против, `0` — сохранить направление. Значение `1` задаёт максимальную скорость `view.rules().turnSpeed()` радиан за игровую секунду. За шаг угол изменится на `turn × turnSpeed / tickRate`. Это доля скорости, не целевой угол. При `throttle=0` корпус поворачивается на месте. Башня управляется отдельно.

`throttle` и `turn` должны быть конечными. Конструктор отвергнет `1.01`, `NaN` и бесконечность с `IllegalArgumentException`; автоматического ограничения до диапазона нет.

### `aim` — абсолютная точка прицела

Передайте `new Vec2(x, y)`. Для танка в `(100, 200)` точка `(200, 200)` находится справа, `(100, 300)` — снизу. Это координаты точки мира, не угол и не смещение от танка. `new Vec2(0, 0)` направляет башню к левому верхнему углу.

Башня поворачивается кратчайшим путём, не быстрее `view.rules().turretSpeed()` радиан за игровую секунду. Поворот корпуса сам по себе не меняет её направление. Передайте `view.me().position()`, чтобы сохранить направление башни: движок так обрабатывает расстояние до прицела меньше `1e-12`.

`aim=null` вызывает `NullPointerException`; `Vec2` с `NaN` или бесконечностью — `IllegalArgumentException`. Сервер также требует `abs(x) ≤ 4 × view.map().width()` и `abs(y) ≤ 4 × view.map().height()`. За пределами этого диапазона он отклоняет команду с `INVALID_AIM`; внутри можно целиться и за край поля.

### `fire` — запрос выстрела

`true` запрашивает выстрел в этом шаге, `false` — нет. Если оружие готово и защиты нет, сервер выпускает один снаряд. Повторяемое `true` означает стрельбу по готовности: переключать `false → true` не требуется. Запрос во время перезарядки пропускается и не ставится в очередь.

Снаряд летит в фактическом направлении башни после её поворота в этом шаге. Сервер не ждёт точного наведения на `aim`. Таймер оружия уменьшается перед проверкой: `view.me().cooldownTicks() ≤ 1` позволяет выстрелить в ближайшем шаге. После выстрела он равен `view.rules().reloadTicks()`.

Под активным щитом и защитой появления стрелять нельзя. `fire=false` не отменяет уже выпущенные снаряды; стены останавливают их.

### `shield` — запрос включения щита

`true` включает щит, если `view.me().shieldCooldownTicks() ≤ 1`. Он защищает уже в шаге включения. Длительность равна `view.rules().shieldDurationTicks()` шагов, включая первый. Перезарядка начинается при включении и равна `view.rules().shieldCooldownTicks()`.

`false` не снимает уже активный щит. Повторяемое `true` включит его снова после перезарядки; одиночный запрос до готовности не ставится в очередь. Под щитом можно двигаться и целиться. Если одновременно запросить выстрел и готовый щит, щит включится и заблокирует выстрел. Если щит ещё не готов и танк не защищён, стрелять можно.

`view.me().shieldTicks()` показывает число будущих защищённых переходов. При значении 1 ближайший переход ещё защищён и стрелять в нём нельзя; в следующем снимке значение станет 0.

### На сколько хватает команды

Сервер применяет свежую команду на ближайшем шаге физики и удерживает её до следующей команды, но не дольше половины игровой секунды. Это сглаживает задержки сети. Для немедленной остановки верните нулевые throttle и turn, false для fire и shield. Если связь оборвалась, после этого срока сервер применяет бездействие. Повтор отправки того же пакета срок не продлевает; при смерти управление сбрасывается. Снаряды, активная защита и таймеры продолжают действовать. Не используйте ожидание, сеть или чтение консоли внутри decide.

`Control.idle(view.me().position())` означает полное бездействие. Если передать в `idle` другую точку, корпус будет стоять, а башня — наводиться на неё. Конструктор с четырьмя аргументами равнозначен пятиаргументному с `shield=false`.

После смерти клиент создаёт новый `MyBot`: поля прежнего экземпляра не переносятся в новую жизнь. Респавн и защиту появления выполняет сервер.

### Если преподаватель меняет условия

Скорости, перезарядку и длительности берите из `view.rules()` **текущего** наблюдения. Преподаватель может менять их в ходе боя; следующий опубликованный шаг содержит новые значения. Не сохраняйте параметры первого снимка как константы на весь матч.

Новые параметры действуют на новые действия. Уже летящие пули сохраняют скорость; начатая перезарядка, активная защита и назначенное ожидание респавна завершаются на прежних условиях. Поэтому остаток таймера своего танка может отличаться от полной длительности в правилах.

## Изменить и проверить

1. Нажмите **Stop** у запущенного `Main`.
2. Измените `MyBot.java`.
3. Запустите `src/test/java/student/MyBotTest.java` как JUnit-тест.
4. Снова запустите `Main` и проверьте поведение на общей арене.

Тесты проверяют допустимость команд в разных стартовых позициях, отсутствие живых противников и новую жизнь после респавна. Они допускают любую корректную стратегию и не требуют сохранять неподвижность. Дописывайте проверки своего поведения рядом.

В окне Maven команда **verify** запускает тесты и проверяет единый стиль Java-кода. Цель **spotless:apply** форматирует код. Оба действия доступны из IDE.

## Если что-то не работает

| Ситуация | Что проверить |
|---|---|
| IDE не видит классы SDK или JUnit | Открыт именно Maven-проект; импорт завершён; JDK выбран 21 |
| Не удаётся подключиться | Сервер работает; адрес открывается в браузере с вашего ноутбука; порт доступен |
| Пароль отклонён | Уточните текущий пароль сервера у преподавателя. Ключ из admin-key.txt предназначен для админки |
| Пароль сервера не задан | Преподавателю нужно сохранить пароль в разделе «Преподавателю» в браузере |
| Клиент ждёт допуска | Преподаватель должен принять регистрацию в админке |
| На арене нет свободного места | Дождитесь места или обратитесь к преподавателю |
| Бот ошибается в `decide` | В консоли есть тип ошибки и строка вашего кода; исправьте её и запустите `Main` заново |
| Преподаватель удалил танк с поля | Клиент не возвращает его автоматически; обсудите повторный вход с преподавателем |
| Клиент для этого сервера уже запущен | Остановите предыдущий `Main` кнопкой Stop; один аккаунт управляется одним процессом |
| Ключ повреждён или сервер его больше не узнаёт | Клиент предложит сохранить старый ключ в резервной копии и зарегистрироваться заново; сначала согласуйте это с преподавателем и уточните пароль сервера |
| Доступ отозван | Преподаватель должен восстановить прежний аккаунт; ключ и очки сохраняются |
| Бот погиб | Оставьте `Main` запущенным: сервер восстановит танк и сохранит счёт |

Полная остановка клиента прерывает связь. Обычное поражение танка её не прерывает.
