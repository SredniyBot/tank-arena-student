# Колония

Твоя колония — класс `MyColony`. Каждый такт игра вызывает его метод `onTick`: колония смотрит на карту и отдаёт приказы рабочим и базе. Первая цель — чтобы рабочий принёс энергию на базу.

## Установка — один раз

1. **IntelliJ IDEA** (Community подходит) и **Git**.
2. **Где хранить проект.** Не в OneDrive: синхронизация мешает сборке и портит файлы. «Документы» и «Рабочий стол» часто лежат в OneDrive — проверь путь. Надёжно — `C:\colony`.
3. **Клонировать.** IntelliJ → **File → New → Project from Version Control** → адрес твоего репозитория → папка, например `C:\colony`. Репозиторий закрытый: IntelliJ попросит войти в GitHub.
4. **JDK 21.** Если IntelliJ пишет, что JDK нет: **File → Project Structure → Project → SDK → Download JDK**, версия 21, любой поставщик. Права администратора не нужны.
5. Дождись, пока Maven скачает зависимости: полоса внизу окна исчезнет.

## Первый запуск

Конфигурации запуска — в списке справа вверху, рядом с ▶.

1. **«Самопроверка»** → ▶. Ждём строку «Можно играть». Если есть строка с `[X]`, сделай то, что написано после «Что сделать».
2. **«Играть»** → ▶. Матч против «бронзы» на карте `steps-4`, просмотр откроется в браузере. Не открылся — открой адрес из строки `Просмотр:` в консоли.
3. Просмотр работает, пока работает программа. Остановить — красный квадрат ■.

## Где писать код

`src/main/java/student/MyColony.java`, метод `onTick`:
- `view` — что видит колония: свои юниты и база, жилы, запас энергии, правила (`view.rules()`);
- `orders` — приказы на этот такт, одному юниту — один.

Отказанный приказ печатается в консоли с причиной, например `такт 12: рабочий 2: впереди стена`. Исключение в `onTick` игру не роняет: колония стоит этот такт, в консоли — красная строка с классом исключения и строкой твоего кода.

Что нужно помнить между тактами, храни в полях объекта, не в `static`: в лестнице несколько матчей подряд, и `static`-поля переходят из матча в матч.

Имя и знак колонии — в `colony.properties`.

**Правила сезона и справочник API** — в материалах курса: `materials/student/colony/rules.md` и `api.md`. Ссылку даст преподаватель.

## Аргументы

**Run → Edit Configurations → «Играть» → Program arguments**:

| Аргумент | Что делает |
|---|---|
| `--opponent=silver` | Соперник: `bronze`, `silver` или `past:<тег>` — твоя же колония с этого тега |
| `--map=training-2` | Карта: `training-2`, `steps-4`, `world-12` или путь к файлу `.json` |
| `--seed=7` | Зерно; с тем же зерном матч повторяется в точности |
| `--ticks=1000` | Длина матча в тактах |
| `--headless` | Без просмотра: итог в консоли, повтор в папке `replays` |

Прошлые матчи открываются в просмотре: на главной странице — список повторов.

## Лестница

**«Лестница»** → ▶: шесть матчей без просмотра — «бронза» и «серебро», зёрна 1–3. Итоги дописываются в `ladder-results.json`, личный рекорд — в консоли. Закоммить этот файл: по нему преподаватель видит, как растёт колония.

## Тесты и проверка на GitHub

Тест `src/test/java/student/MyColonyTest.java` проверяет, что колония играет без исключений. Запуск — ▶ на полях рядом с классом теста.

На каждый push GitHub собирает проект и запускает тесты и самопроверку на Linux и Windows: вкладка **Actions** репозитория. Красная проверка — код не соберётся и у преподавателя.

## Сдать на разбор

На разбор идёт код по тегу — неподвижной метке на коммите.

| Тег | Когда |
|---|---|
| `review-1` | Контрольная точка 1 |
| `review-2` | Контрольная точка 2 |
| `review-1b` | Повторная попытка точки 1 |

Срок — за 48 часов до твоего первого слота, точную дату назовёт преподаватель. Перед тегом: «Самопроверка» проходит, проверка в **Actions** зелёная.

В IntelliJ: **Git → New Tag** → имя тега, затем **Git → Push** с галочкой **Push tags**. В терминале:

```
git tag review-1
git push origin review-1
```

Тег не переставляй. Нашёл ошибку или опоздал — исправь, закоммить и поставь новый тег, например `review-1b`.

Мини-проект и итоговый проект — в своих репозиториях, с теми же правилами тегов: промежуточная версия — `v0.1` (у итогового ещё `v0.2`), сдача — `v1.0`. Сроки — в их заданиях.

Допуск к разбору — низкий порог: проект собирается по тегу, матч доходит до конца, колония приносит доход на открытых картах. Место против «бронзы» в порог не входит. Прогон собирает код без интернета: библиотеки сверх SDK и JUnit — только из списка, который назовёт преподаватель. В прогоне колония работает в изолированном режиме: работа с файлами, запуск программ, `System.exit` и свои потоки запрещены — попытка даёт исключение в `onTick`, а задача для общего пула (`ForkJoinPool`, `CompletableFuture`) просто не выполнится, и её ожидание закончится таймаутом такта. На такт там — 200 мс. Печатать в консоль можно. В `colony.properties` имя колонии — буквы, цифры, пробел, «.», «_», «-», до 40 знаков.

## Предпросмотр: мир на сервере и папка `sdk-repo`

- **Мир на сервере.** Сохрани токен одной строкой в файл `%USERPROFILE%\.colony\token`, убери `#` перед строкой `server=` в `colony.properties` и запусти «Играть». Без этой строки игра локальная, как раньше; `--local` играет локально и со строкой.
- **`sdk-repo/` — временное решение на время предпросмотра.** SDK ещё не опубликован на сайте, поэтому лежит прямо в репозитории: Maven берёт его из этой папки, а сайт — второй источник. Когда SDK появится на сайте, папку и первый репозиторий в `pom.xml` уберут.

## Обновление SDK

Перед парой преподаватель меняет версию SDK в `pom.xml` твоего репозитория. Забери изменения (**Git → Update Project**), затем **Maven → Reload**. Если самопроверка пишет, что SDK устарел, сделай, что она советует.

## Если не работает

- Начни с «Самопроверки»: она проверяет Java, версию SDK, папку проекта, короткий матч и порт просмотра и называет одно действие.
- Maven не скачивает SDK — проверь интернет. В классе без интернета — см. комментарий в `pom.xml`.
- Порт просмотра занят — игра возьмёт другой и напечатает адрес.
- Кракозябры вместо русских букв бывают в `cmd.exe`. Запускай из IntelliJ.
