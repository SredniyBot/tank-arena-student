# Самостоятельные участники: правила версии 3.5

Java 21, протокол 2.13. Профиль сервера — `config/combat.properties`. Любой танк может повредить любой другой. В игре нет команд, грузов, захвата, общей видимости или серверного канала произвольных сообщений.

Реализованы выбранные правила 1, 2, 3, 4, 5, 9, 10, 11, 13, 19:

| Правило                      | Поведение                                                                                                                                                                                                                                                                                                                     |
| ---------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1. Конечный боезапас         | Новая жизнь начинается с 12 снарядов; максимум 24. Фактический выстрел расходует один. Обычная перезарядка восстанавливает готовность оружия, но не снаряды.                                                                                                                                                                  |
| 2. Общий запас               | Ящик боеприпасов вмещает 12 единиц, получает одну каждые 2 игровые секунды. На дистанции до 48 единиц с прямой видимостью танк автоматически получает по одному снаряду раз в 0,25 с, пока есть запас и место.                                                                                                                |
| 3. Разные места пополнения   | Боеприпасы, ремонт и модуль башни находятся в разных точках. Ничего не нужно перевозить или доставлять. Динамическое состояние видно только в личном обзоре.                                                                                                                                                                  |
| 4. Ремонт с остановкой       | В пределах 48 единиц от ремонтного ящика: нулевая тяга, нулевой поворот и `fire=false`. Каждые 3 игровые секунды восстанавливается один HP и расходуется единица запаса. Движение, запрос огня, урон либо отсутствие доступного ремонтного ящика сбрасывают незавершённый прогресс. Уже восстановленное здоровье сохраняется. |
| 5. Разрушаемые расходники    | Все ящики имеют 3 HP. Снаряд наносит один урон и исчезает; стены и танки перед ящиком перекрывают попадание. Разрушение уничтожает запас. Через 20 с объект восстанавливается с одной единицей, затем пополняется в обычном темпе.                                                                                            |
| 9. Улучшение до гибели       | Подбор модуля даёт +35% к скорости поворота башни. Улучшение не складывается, исчезает при гибели и не меняет корпус или урон. Запас модуля — один, восстановление одной единицы раз в 30 с.                                                                                                                                  |
| 10. Одна личная награда      | Автор уничтожения получает +100. Отдельный урон очков не даёт. Если несколько участников нанесли смертельные попадания в одном физическом тике, выбирается один получатель по детерминированному циклическому приоритету, меняющемуся с тиком и целью. Дополнительных наград нет.                                             |
| 11. Цена гибели              | Гибель даёт −100. Счёт может быть отрицательным. Он привязан к аккаунту, сохраняется при переподключении и в серверном хранилище.                                                                                                                                                                                             |
| 13. Личный обзор             | Радиус по умолчанию 340; стены закрывают обзор. Клиент получает свой танк, видимые живые танки, снаряды и расходники; скрытые координаты не передаются. Полный снимок и повтор доступны преподавателю.                                                                                                                        |
| 19. Новое место после гибели | Через 3 с сервер ищет свободную точку вдали от живых танков и предыдущего положения. Если безопасного места нет, появление откладывается. Новая жизнь получает 1,5 с защиты.                                                                                                                                                  |

Ремонтный запас вмещает 3 HP и пополняется на один HP каждые 10 с. Недостающий запас не резервируется за участником. При конкуренции в одном тике порядок обслуживания циклически меняется; номер слота не даёт постоянного преимущества.

Новая жизнь означает базовый танк, свежий боезапас и новый экземпляр бота. Живой танк, добровольно покидающий поле либо потерявший связь на 15 с, считается выведенным из боя: −100 без награды другому участнику. Это не позволяет бесплатно восстанавливать здоровье и снаряды перезапуском программы. Исключение преподавателем и перезапуск раунда — административные операции. Перед отладкой с остановками учитывайте цену выхода; игровой счёт не является оценкой работы по Java.

Счёт в интерфейсе — накопленный личный счёт сессии сервера, `100 × (уничтожения − гибели)`. Новый бой преподавателя меняет `roundId` и игровое поле, но не обнуляет историю аккаунтов.

## Запуск преподавателя

Откройте Maven-проект сервера на Java 21. Запустите `edu.arena.server.bootstrap.ServerMain` из IDE с рабочим каталогом проекта сервера. Без аргументов загружается `config/combat.properties`.

Собранный сервер также запускается командой `java -jar arena-server/target/arena-server.jar config/combat.properties`. Это дополнительный способ; студенту достаточно `student.Main` в IDE.

После старта:

1. Откройте `http://127.0.0.1:8080/#teacher`, войдите с административным ключом из `data-independent/identity/admin-key.txt`.
2. Задайте общий пароль регистрации. Передайте участникам адрес сервера и пароль, не административный ключ.
3. Принимайте заявки в панели преподавателя. Один участник может войти без ожидания остальных.
4. Откройте `/combat.html` для просмотра боя. Преподаватель использует административный ключ, студент — личный токен, путь к которому печатает Java-программа.

Для доступа с других компьютеров измените `network.host` на нужный интерфейс, например `0.0.0.0`, и разрешите вход на выбранный порт. По умолчанию сервер привязан к localhost. Старые профили доставки не включают эти правила.

`capacity.participants` — вместимость, а не обязательное число игроков. Для увеличения числа мест задайте не меньше `capacity.participants + 4` потоков `network.workers`; поддерживаемый формат допускает 2–64 места, фактически активным может быть один танк. Штатный профиль: 16 мест, физика 20 Гц, общее окно управления 2 тика. Преподаватель может менять основные скорости и таймеры через существующую панель условий. Параметры запасов и модуля сейчас определяются в `CombatState` и `CombatMechanics`; они не выведены в административную форму.

## Где реализовано

- `arena-core/.../combat`: оборудование, расходники, личный публичный контракт `CombatBot` / `CombatObservation`.
- `arena-core/.../engine/CombatMechanics`: расход и пополнение запасов, ремонт, улучшения, разрешение одновременных уничтожений.
- `arena-core/.../engine/ArenaEngine`: движение, снаряды, столкновения с ящиками, запрет стрельбы без боезапаса, скорость башни.
- `arena-core/.../recon/ReconEngine`: авторитетный личный обзор и жизненный цикл. Название пакета историческое; пользовательский контракт независимого режима не содержит команд.
- `arena-server/.../match/LiveArenaRoom`, `LiveScores`: общий такт, учёт аккаунтов и сохранение личного результата.
- `arena-client/.../CombatApplication`: подключение из IDE поверх существующего SDK.
- `arena-server/src/main/resources/web/combat.*`: просмотр поля и состояния расходников.

Версия подготовлена без запуска тестов, нагрузочных прогонов или браузерной проверки. Выполнена только сборка без тестов. Баланс, удобство и пользу договорённостей эта сборка не подтверждает.
