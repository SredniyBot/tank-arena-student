# API студента

Программа запускается из `student.Main` в IDE. `BotApplication.run(MyBot::new)` обслуживает подключение и создаёт нового бота для каждой жизни. Студент пишет игровые решения в `MyBot`.

В консоли Main введите адрес сервера, имя танка и общий пароль сервера от преподавателя. Ключ преподавателя из `admin-key.txt` здесь не используется. При первой регистрации дождитесь допуска преподавателя. SDK сохраняет личный токен отдельно от проекта, в домашнем каталоге `.tank-arena/players`; повторный запуск использует его без ввода общего пароля. Без сервера решения проверяются через `MyBotTest` в IDE.

## Контракт

```java
public interface Bot {
    Control decide(Observation view);
}
```

Исходный ответ:

```java
@Override
public Control decide(Observation view) {
    return Control.idle(view.me().position());
}
```

Бот только появляется и стоит. Он не выбирает цель, не двигается, не наводится, не стреляет и не включает щит. Вы сами решаете, когда понадобятся методы, объекты, состояния или собственные интерфейсы. Готового разделения управления на компоненты нет.

`Bot` и `Observation` находятся в пакете `edu.arena.core.bot`; `Control`, `Tank`, `Vec2` — в `edu.arena.core.model`.

## Что читать

| Выражение | Содержание |
| --- | --- |
| `view.me()` | Ваш танк |
| `view.self()` | Номер слота вашего танка в снимке |
| `view.opponents()` | Другие живые танки |
| `view.state().tick()` | Номер завершённого игрового шага |
| `view.state().tanks()` | Все слоты, включая погибших и свободные |
| `view.state().projectiles()` | Снаряды: владелец, позиция и скорость |
| `view.state().events()` | События этого шага |
| `view.map().walls()` | Прямоугольные препятствия |
| `view.map().width()` / `height()` | Размеры поля |
| `view.rules()` | Параметры текущего боя |

Снимок неизменяем. Списки нельзя сортировать или дополнять на месте; для изменений создайте свою коллекцию. `Tank` и `Vec2` — `record`: `position()` читает значение, `Vec2.add(...)` возвращает новый вектор.

Свободный слот представлен танком с HP 0. Номер слота не является постоянным ID человека: после выхода место может занять другой участник. Список `opponents()` может быть пустым.

## Что вернуть

```java
new Control(throttle, turn, aim, fire, shield)
```

| Аргумент | Значение |
| --- | --- |
| `throttle` | Конечное число от −1 до 1: назад, остановка, вперёд вдоль корпуса |
| `turn` | Конечное число от −1 до 1: доля максимальной скорости поворота корпуса |
| `aim` | Точка мира `Vec2`, в сторону которой поворачивается башня |
| `fire` | Запрос выстрела |
| `shield` | Запрос включения щита |

`aim` — точка, не угол и не смещение. Её координаты должны быть конечными; допустимо `abs(x) ≤ 4 × map.width()` и `abs(y) ≤ 4 × map.height()`. `null`, `NaN`, бесконечность и выход за диапазон недопустимы. Если точка совпадает с центром своего танка, башня сохраняет направление.

Прицел и выстрел независимы. Сервер ограничивает скорость поворота башни, проверяет перезарядку и защиту. `fire=true` не означает мгновенный выстрел или попадание. Под активным щитом и защитой появления стрелять нельзя.

## Координаты и время

Начало координат находится слева вверху. X растёт вправо, Y — вниз. Нулевой угол направлен вправо; положительный поворот на экране идёт по часовой стрелке. Углы измеряются в **радианах**, размеры — в единицах игрового мира, не в пикселях браузера.

| Поле | Единицы |
| --- | --- |
| `position()` | Координаты центра корпуса |
| `velocity()` | Единицы мира за игровую секунду |
| `heading()` / `gunHeading()` | Направление корпуса / башни в радианах |
| `health()` | HP |
| `cooldownTicks()` | Шаги до готовности оружия |
| `shieldTicks()` | Шаги оставшейся защиты |
| `shieldCooldownTicks()` | Шаги до готовности щита |
| `rules.tickRate()` | Шаги физики за игровую секунду |

Игровое время: `tick / (double) rules.tickRate()`. На слабом сервере игра может идти медленнее реального времени; опирайтесь на `tick`, а не на часы компьютера. Перезарядка и респавн одинаковы для участников и не ускоряются частыми запросами.

## Вызовы и память

SDK вызывает `decide` для нового полученного шага живого танка. При повторе сетевого запроса передаётся уже вычисленная команда. Пропущенные шаги не пересчитываются задним числом. Возвращайте результат быстро: сеть, чтение консоли, файлов и `sleep` не должны находиться внутри `decide`.

Фабрика `MyBot::new` создаёт отдельный экземпляр для новой жизни. Поля экземпляра сохраняются между решениями этой жизни и подходят для вашей памяти. Изменяемые `static`-поля могут пережить смерть и смешать состояние нескольких ботов. Смена жизни определяется даже тогда, когда клиент пропустил кадр смерти.

## Проверка своего решения

Откройте тест в `src/test/java/student` и запустите его кнопкой Run в IDE. Общая проверка требует допустимого `Control`, а не бездействия. Дополните её тестом собственного правила: конкретный снимок, ожидаемый результат и граничный случай.

Сначала проверяйте добавленное действие. Поворот сам по себе может не принести ни одного уничтожения. Для сравнения боевых версий сохраняйте условия опыта и seed собственного генератора случайных чисел. Успех в локальном тесте не доказывает своевременную работу через сеть.

Респавн и короткую защиту появления выполняет сервер. Они не относятся к интеллекту исходного бота и не требуют студенческой реализации.
