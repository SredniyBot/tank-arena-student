# API студента

Программа запускается из `student.Main` в IDE. `BotApplication.run(MyBot::new)` обслуживает подключение и создаёт нового бота для каждой жизни. Студент пишет игровые решения в `MyBot`.

В консоли Main введите адрес сервера, имя танка и общий пароль сервера от преподавателя. Ключ преподавателя из `admin-key.txt` здесь не используется. При первой регистрации дождитесь допуска преподавателя. SDK сохраняет личный токен отдельно от проекта, в домашнем каталоге `.tank-arena/players`; повторный запуск использует его без ввода общего пароля. Без сервера решения проверяются через `MyBotTest` в IDE.

## Контракт

```java
public interface Bot {
    Control decide(Observation view);
}
```

Исходный ответ:

```java
@Override
public Control decide(Observation view) {
    return Control.idle(view.me().position());
}
```

Бот только появляется и стоит. Он не выбирает цель, не двигается, не наводится, не стреляет и не включает щит. Вы сами решаете, когда понадобятся методы, объекты, состояния или собственные интерфейсы. Готового разделения управления на компоненты нет.

`Bot` и `Observation` находятся в пакете `edu.arena.core.bot`; `Control`, `Tank`, `Vec2` — в `edu.arena.core.model`.

## Что читать

| Выражение | Содержание |
| --- | --- |
| `view.me()` | Ваш танк |
| `view.self()` | Номер слота вашего танка в снимке |
| `view.opponents()` | Другие живые танки |
| `view.state().tick()` | Номер завершённого игрового шага |
| `view.state().tanks()` | Все слоты, включая погибших и свободные |
| `view.state().projectiles()` | Снаряды: владелец, позиция и скорость |
| `view.state().events()` | События этого шага |
| `view.map().walls()` | Прямоугольные препятствия |
| `view.map().width()` / `height()` | Размеры поля |
| `view.rules()` | Параметры текущего боя |

Снимок неизменяем. Списки нельзя сортировать или дополнять на месте; для изменений создайте свою коллекцию. `Tank` и `Vec2` — `record`: `position()` читает значение, `Vec2.add(...)` возвращает новый вектор.

Свободный слот представлен танком с HP 0. Номер слота не является постоянным ID человека: после выхода место может занять другой участник. Список `opponents()` может быть пустым.

## Что вернуть

```java
new Control(throttle, turn, aim, fire, shield)
```

### `throttle`: движение вдоль корпуса

Конечное число от **−1 до 1**. `1` — вперёд со скоростью `view.rules().moveSpeed()`, `−1` — назад с такой же скоростью, `0.5` — вперёд с половинной скоростью. `0` прекращает перемещение: инерции нет. Задний ход не разворачивает корпус или башню.

Это доля скорости, а не ускорение и не расстояние. За один свободный шаг танк проходит `abs(throttle) × moveSpeed / tickRate` единиц мира. Препятствие сокращает перемещение; столкновение с другим танком может отменить его. `throttle` и `turn` действуют вместе: сначала рассчитывается новое направление корпуса, затем перемещение вдоль него.

### `turn`: скорость поворота корпуса

Конечное число от **−1 до 1**. Положительное значение поворачивает корпус **по часовой стрелке**, отрицательное — против, `0` сохраняет направление. `1` означает максимальную угловую скорость `view.rules().turnSpeed()`, `0.5` — половину этой скорости. За шаг угол изменяется на `turn × turnSpeed / tickRate` радиан.

`turn` не задаёт конечный угол. Можно поворачивать на месте при `throttle=0` или одновременно ехать и поворачивать. Башня управляется отдельно через `aim`.

Значения обоих числовых полей проверяются при создании `Control`: `1.01`, `NaN` и бесконечность вызывают `IllegalArgumentException`. Автоматического ограничения до диапазона нет.

### `aim`: абсолютная точка прицела

`new Vec2(x, y)` — точка мира, в сторону которой нужно повернуть башню. Это не угол и не смещение от танка. Если танк стоит в `(100, 200)`, точка `(200, 200)` находится справа от него, `(100, 300)` — снизу. `new Vec2(0, 0)` означает левый верхний угол поля, а не «не целиться».

Башня поворачивается кратчайшим путём, не быстрее `view.rules().turretSpeed()` радиан за игровую секунду. Направление считается от позиции танка в исходном снимке. `view.me().position()` сохраняет прежнее направление башни; движок считает нулевым расстояние меньше `1e-12`. Поворот корпуса сам по себе башню не разворачивает.

Координаты должны быть конечными: `Vec2` отвергает `NaN` и бесконечность с `IllegalArgumentException`; `Control` отвергает `aim=null` с `NullPointerException`. Сервер также требует `abs(x) ≤ 4 × view.map().width()` и `abs(y) ≤ 4 × view.map().height()`. В этих пределах целиться за край поля допустимо. При выходе за пределы сервер отклоняет команду с `INVALID_AIM`.

### `fire`: удержание запроса выстрела

`true` запрашивает выстрел в этом шаге; `false` — нет. Сервер выпускает не более одного снаряда за шаг, если оружие готово и танк не защищён щитом или защитой появления. Запрос во время перезарядки пропускается и не ставится в очередь. Для стрельбы по готовности возвращайте `true` в следующих командах: переключение `false → true` не требуется.

Перед проверкой выстрела таймер оружия уменьшается на один. Поэтому `view.me().cooldownTicks() ≤ 1` означает, что в ближайшем шаге оружие уже сможет выстрелить. После выстрела таймер равен `view.rules().reloadTicks()`. Частые сетевые запросы не сокращают этот интервал.

Снаряд летит в фактическом направлении башни **после её поворота в этом шаге**. Сервер не ждёт, пока башня точно наведётся на `aim`: прицел и разрешение на выстрел — разные решения. `fire=false` не отменяет уже летящие снаряды. Стены останавливают их.

### `shield`: запрос защитного интервала

`true` запрашивает включение щита. Он срабатывает, если `view.me().shieldCooldownTicks() ≤ 1`, и защищает уже в шаге включения. Длительность — `view.rules().shieldDurationTicks()` шагов **вместе с шагом включения**. Перезарядка начинается при включении, а не после исчезновения щита, и равна `view.rules().shieldCooldownTicks()`.

`false` не выключает активный щит. Повторяемое `true` включит его снова, как только завершится перезарядка. Одиночный запрос до готовности пропускается и не ставится в очередь.

Под щитом можно ехать, поворачивать корпус и наводиться, но нельзя стрелять. Если одновременно передать `fire=true` и `shield=true`, готовый щит включится и заблокирует выстрел. Если щит ещё не готов и активной защиты нет, выстрел допустим. Защиту появления назначает сервер; для неё не требуется возвращать `shield=true`.

### Несколько отдельных команд

Каждая строка ниже — самостоятельный пример значения, которое можно вернуть из `decide`. Это команды для одного шага, без выбора цели или стратегии.

```java
// Стоять, сохранить башню.
Control.idle(view.me().position());

// Вперёд с половинной скоростью.
new Control(0.5, 0, view.me().position(), false, false);

// Поворот корпуса против часовой стрелки.
new Control(0, -1, view.me().position(), false, false);

// Наводиться на точку, не стрелять.
new Control(0, 0, new Vec2(800, 400), false, false);

// Запросить выстрел вдоль башни.
new Control(0, 0, view.me().position(), true, false);

// Запросить щит.
new Control(0, 0, view.me().position(), false, true);
```

У `Control.idle(aim)` неподвижен корпус, но башня всё равно наводится на переданный `aim`. Для полного бездействия передавайте текущую позицию своего танка. Конструктор из четырёх аргументов равнозначен пятиаргументному с `shield=false`.

## Координаты и время

Начало координат находится слева вверху. X растёт вправо, Y — вниз. Нулевой угол направлен вправо; положительный поворот на экране идёт по часовой стрелке. Углы измеряются в **радианах**, размеры — в единицах игрового мира, не в пикселях браузера.

| Поле | Единицы |
| --- | --- |
| `position()` | Координаты центра корпуса |
| `velocity()` | Единицы мира за игровую секунду |
| `heading()` / `gunHeading()` | Направление корпуса / башни в радианах |
| `health()` | HP |
| `cooldownTicks()` | Таймер оружия; 0 или 1 позволяют выстрелить в ближайшем переходе |
| `shieldTicks()` | Число будущих переходов, в которых танк ещё защищён |
| `shieldCooldownTicks()` | Таймер щита; 0 или 1 позволяют включить его в ближайшем переходе |
| `rules.tickRate()` | Шаги физики за игровую секунду |

Игровое время: `tick / (double) rules.tickRate()`. На слабом сервере игра может идти медленнее реального времени; опирайтесь на `tick`, а не на часы компьютера. Перезарядка и респавн одинаковы для участников и не ускоряются частыми запросами.

Таймер в снимке описывает состояние **после** завершённого шага. Например, после включения щита на 20 шагов снимок покажет `shieldTicks=19`: первый защищённый переход уже прошёл. При `shieldTicks=1` ближайший переход ещё защищён и стрелять в нём нельзя, хотя в следующем снимке таймер станет нулевым.

## Изменение условий во время игры

Преподаватель может менять скорости корпуса, башни и новых снарядов, перезарядку оружия и параметры щита без остановки сервера. Актуальные значения приходят в `view.rules()` следующего опубликованного шага. Читайте их из текущего `Observation`, не сохраняйте первоначальные значения как постоянные настройки бота. Например, длительность новой перезарядки в игровых секундах — `view.rules().reloadTicks() / (double) view.rules().tickRate()`.

Уже выпущенный снаряд сохраняет свою скорость; начатая перезарядка, активный щит и уже назначенное ожидание респавна завершаются на прежних условиях. Новые действия используют новые правила. Текущие таймеры своего танка поэтому могут отличаться от полной длительности в `view.rules()`.

## Вызовы и память

SDK вызывает `decide` для нового полученного шага живого танка. При повторе сетевого запроса передаётся уже вычисленная команда. Пропущенные шаги не пересчитываются задним числом. Возвращайте результат быстро: сеть, чтение консоли, файлов и `sleep` не должны находиться внутри `decide`.

Одна команда действует один шаг. При отсутствии принятой команды сервер применяет бездействие: прекращает перемещение, сохраняет направление башни, не запрашивает выстрел и новый щит. Он не продолжает последнюю команду автоматически. Активная защита, снаряды и таймеры продолжают действовать. Для непрерывного движения или огня возвращайте нужные поля снова при следующем вызове.

Фабрика `MyBot::new` создаёт отдельный экземпляр для новой жизни. Поля экземпляра сохраняются между решениями этой жизни и подходят для вашей памяти. Изменяемые `static`-поля могут пережить смерть и смешать состояние нескольких ботов. Смена жизни определяется даже тогда, когда клиент пропустил кадр смерти.

## Проверка своего решения

Откройте тест в `src/test/java/student` и запустите его кнопкой Run в IDE. Общая проверка требует допустимого `Control`, а не бездействия. Дополните её тестом собственного правила: конкретный снимок, ожидаемый результат и граничный случай.

Сначала проверяйте добавленное действие. Поворот сам по себе может не принести ни одного уничтожения. Для сравнения боевых версий сохраняйте условия опыта и seed собственного генератора случайных чисел. Успех в локальном тесте не доказывает своевременную работу через сеть.

Респавн и короткую защиту появления выполняет сервер. Они не относятся к интеллекту исходного бота и не требуют студенческой реализации.
